About

Fintech engineering, end to end.

It started in 2019, when I walked onto campus and decided to build my first Android app and a website from scratch. That rabbit hole of Java, XML, HTML and CSS never let me go, and I've been building ever since.

Today I own the Spotcash mobile banking platform at Tangazoletu across the whole stack: Flutter apps on the front, Spring Boot microservices behind them, and integrations into each client's core banking system. The systems I work on move real money for real people every day, so I care about clean architecture, rock-solid security, and making change possible through configuration instead of a new release.

Next, I'm going deeper into mobile and application security: device attestation, secure payload handling and vulnerability assessment for financial apps.

Consolidated Loan Module & Secured Loans

One JSON-driven loan engine for every loan type, rolled out to SACCOs running different core banking systems.

The problem

Every loan type had its own screens, and every new product or client rule meant a new app release. Secured loans, with guarantors, collateral and documents, also had to work against several different core banking systems.

What I built

  • Designed and built a single consolidated loan screen that is fully configured by JSON: e-loans, digital loans and secured loans share one engine.
  • A tabbed secured-loan journey (eligibility, loan details, guarantors, securities, documents, review) with resume, cancellation, guarantor acknowledgement and a live loan calculator.
  • Per-client and per-product rules in configuration: guarantor minimums and approvals, partial loan offsetting, loan charges fetched from core banking, mandatory documents and self-guarantee auto-approval.
  • The backend APIs in the App Switch (Spring Boot), bridge configuration into each client's core banking system, and the API specifications their vendors built against.

Outcome

New loan products and client rules now ship through configuration, without an app release. Secured loans are live in production for multiple SACCOs.

Stack

  • Flutter
  • Dart
  • Java
  • Spring Boot
  • Oracle
  • SOAP / XML
  • Dynamics 365 BC
Tangazoletu · Spotcash · 2025–26

Mobile Banking Security Hardening

Fraud usually targets members, not systems. A tricked OTP or a borrowed PIN is often all it takes.

What I built

  • Device fingerprint capture and update, with logins from new, unrecognised devices blocked, so an account only works on its registered handset.
  • OTP SMS and email messages that state their purpose and, where possible, the transaction amount, so members can spot a fraudulent request before approving it.
  • Hardened PIN reset, OTP validation, login and session handling, and masked sensitive keys and tokens in server logs.

Outcome

Accounts are bound to their registered devices, and every OTP tells members exactly what they are approving.

Stack

  • Flutter
  • Spring Boot
  • JWT
  • AES

Personal project · 2026 · In development

Woza: offline Bluetooth messenger

Messaging apps assume an internet connection. Woza assumes nothing: chat and share files with people nearby over Bluetooth, with no account, Wi-Fi, mobile data or server.

What I built

  • BLE discovery and L2CAP channels in Kotlin behind a Flutter UI. Discovery only runs while the user turns Nearby on, and a recipient must accept a request before anyone can chat.
  • End-to-end encryption on every link with the Noise XX handshake, plus security codes to verify in person.
  • Resumable photo, video and file transfer up to 1 GB, verified with SHA-256. Messages queue offline and send on reconnect.
  • The details that make it feel finished: swipe to reply, edit and delete-for-everyone, photo albums, captions, notifications, app lock with PIN or fingerprint, and light and dark mode.

Status

Android MVP in active development. Woza is a working title.

Tangazoletu · 2026

Loan Draft Auto-Expiry Engine

Loan applications that members start and never submit should not linger for ever, holding guarantors' requests open.

What I built

  • A scheduled job in the Schedule Task microservice that expires stale secured-loan drafts, cancels them in core banking with a clear reason, and closes their pending guarantor requests.
  • Multithreaded batch processing on a bounded worker pool, so a large backlog never ties up the server.
  • Every setting (expiry period, batch size, threads and delay) lives in the database per client, so dozens of SACCOs can each have their own policy and changes apply without a redeploy or restart.

Outcome

Each SACCO's draft policy is a database row, not a release.

  • Java
  • Spring Boot
  • Oracle
  • Concurrency
